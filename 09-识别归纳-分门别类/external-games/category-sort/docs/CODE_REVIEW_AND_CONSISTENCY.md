### 3. 小关生成规则

源表要求：根据配置表生成关卡；先展示图示，后展示选项；选项由 1 个正确选项和其他干扰选项组成；图示和正确项从目标池随机且不重复；干扰项从干扰池随机。

修复后的实现：

1. `makeRound()` 从当前关卡的目标池中随机抽取一个目标类别。
2. 图示与正确选项从该目标类别的物品中抽取，并确保物品 ID 不重复。
3. 干扰项优先从“完整范围 - 目标池”抽取；如果该干扰池数量不足，则依次回退到“同范围非目标类别”和“全局非目标类别”，保证选项数量完整。
4. `renderRound()` 分阶段执行：先渲染图示，再触发图示移动和提示音，最后渲染选项飞入动画。

### 4. 小关结束与通关判定

源表的修改逻辑明确：小关结束条件为倒计时为 0 或连续选错 2 次；PassTarget 是小关结束后的通关判定条件，不是即时结束条件。

修复后的实现：

| 规则 | 实现位置 | 状态 |
|---|---|---|
| 倒计时为 0 结束 | `startTimer()` 调用 `finishStage("倒计时结束")` | 已实现 |
| 连续选错 2 次结束 | `chooseOption()` 检查 `state.wrongStreak >= 2` | 已实现 |
| 达到 PassTarget 不立即结束 | `chooseOption()` 不再因正确次数达标而结束 | 已实现 |
| 结束后以 `correctCount >= passTarget` 判定通关 | `finishStage()` | 已实现 |

## 二、发现的问题与修复

### 问题 1：关卡类别深度解释错误

原工程直接把 `数值(4).xlsx` 的 `Level.Type` 当作类别深度使用。但该列在 100 关中均为 `0`，如果照此解释，全部关卡都会变成一级类别训练。这样会导致 13-90 关的二级类别训练和 91-100 关的三级类别训练失效。

修复：

1. `数值(4).xlsx` 的 `Level` 表继续作为计时、选项数、基础分、奖励分、PassTarget 的权威来源。
2. 类别深度和完整目标范围改从 `关卡配置(2).xlsx` 的“目标池”标记推导，例如 `N=(A,F)` 对应一级类别，`n=(a,s)` 对应二级类别，`n=(u,z)` 对应三级类别。
3. 修复后的关卡深度分布为：1-12 关一级类别，13-90 关二级类别，91-100 关三级类别。
4. 映射结果写入 `source/data_mapping_summary.json` 和 `source/runtime_game_data.json`。

### 问题 2：目标池与干扰池混淆

原工程把目标池中的其他类别当作干扰项。源表写法是“干扰池 = 完整范围 - 目标池”，两者不完全等价。

修复：

`makeRound()` 现在优先使用 `scope - target` 生成干扰项。只有在源表范围本身不足以凑齐选项时，才启用安全兜底池。

### 问题 3：正确判定过宽

原工程用“是否属于目标类别”判断正确，而不是用本轮指定的正确项判断。虽然当前生成逻辑通常只有一个同类选项，但这样会留下隐藏缺陷：如果未来配置或兜底池引入同类别干扰，多个选项都会被判为正确。

修复：

`chooseOption()` 改为 `item.id === state.current.correct.id`。选项中仍只放入一个指定正确项，符合“1 个正确选项 + 干扰项”的策划描述。

### 问题 4：图示与选项的展示时序不够严格

原工程在同一次渲染中同时创建图示和选项，主要依赖 CSS 延迟动画制造“后出现”的视觉效果。严格性不足。

修复：

`renderRound()` 改为三段式：

1. 立即展示图示。
2. 约 560ms 后显示提示文字并播放提示音。
3. 约 780ms 后生成选项按钮并允许点击。

这使逻辑层面也符合“先展示图示，后展示选项”。

### 问题 5：异步计时器存在潜在串场风险

原工程在选择后使用 `setTimeout(makeRound)`。如果玩家在结算后快速开始下一关，旧的延迟回调理论上可能影响新关卡。

修复：

新增 `stageToken` 和 `roundToken`。所有延迟回调都必须匹配当前 token，否则自动失效。

### 问题 6：`finishStage(forcePass, reason)` 参数语义不严谨

原工程传入 `forcePass`，但函数内部实际忽略该参数并重新计算通关状态，容易误导后续维护。

修复：

函数改为 `finishStage(reason)`，通关状态统一由 `correctCount >= passTarget` 计算。

### 问题 7：缺少面向新手的完整教程

原工程只有帮助图，没有解释“PassTarget 不即时结束”“为什么达标后还继续”“积分如何计算”等关键规则。

修复：

1. 首页、欢迎页、游戏页均增加“新手教程”入口。
2. 帮助弹窗增加教程切换按钮。
3. 新增 `docs/BEGINNER_TUTORIAL.md`，提供完整新手教程与常见问题。

### 问题 8：源表存在一个物品命名不一致

`数值(4).xlsx` 的 `Item` 表中，ID 28 是“豌豆藤”；`关卡配置(2).xlsx` 的“物品属性配置”中，ID 28 是“扁豆藤”。

处理：

运行时采用 `数值(4).xlsx` 的 `Item` 表作为物品清单权威来源，因此 ID 28 保持“豌豆藤”。该不一致记录在 `source/data_mapping_summary.json` 中。

## 四、后续维护建议

1. 若继续调整关卡表，优先修改 `数值(4).xlsx` 的 `Level` 表中的计时、分数、PassTarget；目标范围标记仍应保持在 `关卡配置(2).xlsx` 中。
2. 若需要让 13-30 关覆盖全部二级类别，需要把 `Target` 数字扩展到 0-18，或明确规定该组使用完整 `a-s` 范围。
3. 若将来接入真实美术素材，应保持文件名不变或同步更新 `src/data.js` 中的 `asset` 路径。
4. 若要做线上版本，建议把 `src/data.js` 拆成纯 JSON，并由游戏逻辑异步加载，便于后续版本管理。
