# 《静默池塘》详细修复与验证报告

修复日期：2026-05-13  
修复对象：`静默池塘_精致素材版_完整游戏.zip` 的游戏源码、配置、素材接入与说明文档。  
修复原则：不改动 50 关逐关数值；只修复判定缺陷、运行时一致性、素材接入、UI 口径和扩展接口。

## 1. 修复结论

当前修复版已经解决上一轮代码审查中影响交付定稿的主要问题。最关键的 P1 缺陷已经修复：最后一条红鲤鱼命中后立即冻结倒计时并进入结算态，动画延迟不会再造成“已完成投食却因倒计时归零失败”，也不会少算最后 0.36 秒左右的剩余时间分。

本版本将 `Fault` 统一解释为“可错次数”：错误次数超过 `Fault` 才失败。例如 `Fault=2` 表示前两次错误可容错，第 3 次错误失败。该语义已经写入 `data.json` / `data.js` 的 `faultPolicy: "allowed_mistakes"` 和 `faultPolicyNote`。

50 关正式数值未被重写。复核结果显示，修复版 `data.json.levels` 与原精致素材版项目中的 `data.json.levels` 完全一致；本轮只新增顶层解释性配置字段，并补充鱼体大小说明。

## 2. 逐项修复明细

### SP-AUDIT-001｜P1｜最后投食成功后的倒计时竞态

原问题：最后一条红鲤鱼投食成功后，旧代码等待成功动画结束再结算，期间倒计时仍继续扣减。若玩家在临近 0 秒时完成最后一次投食，可能被倒计时失败覆盖；即使正常过关，也会少算动画延迟期间的剩余时间。

修复方式：命中最后一条红鲤鱼的瞬间记录 `remainingAtClear = round1(timer)`，立即进入 `resolving` 状态并冻结玩家输入、冷却和计时。成功动画展示结束后调用 `completeLevel(remainingAtClear)`，用冻结时间结算得分和奖励。`update()` 中也调整了帧内顺序：先处理本帧已到达的投食弹，再根据 `timerExpired` 决定是否失败，避免同一帧内命中和归零的排序误判。

### SP-AUDIT-002｜P2｜Fault 字段语义

原问题：字段表头含“可错”语义，但旧逻辑是“错误达到 Fault 即失败”，与中文口径不一致。

修复方式：默认策略改为 `allowed_mistakes`，即 `errors > Fault` 才失败。HUD、帮助文案、失败文案同步改成“错误/可错”“超过可错次数失败”。代码保留兼容分支：如果未来产品明确 `Fault` 是失败阈值，可将顶层策略改为 `failure_threshold`，使逻辑回到“达到阈值失败”。

### SP-AUDIT-003｜P2｜鱼体大小配置未被运行时使用

原问题：配置中存在 `fishSize.redPercent` 和 `fishSize.blackPercent`，但鱼的绘制尺寸、点击半径、边界碰撞和障碍碰撞仍使用固定值。

修复方式：新增鱼体缩放读取逻辑。红鱼读取 `RedSize / RedPercent / RedFishSize / RedFishPercent / redPercent`，干扰鱼读取 `BlackSize / BlackPercent / BlackFishSize / BlackFishPercent / blackPercent`。运行时把 scale 写入鱼对象，并同步用于绘制尺寸、命中半径、出生间距、边界碰撞和障碍碰撞。

### SP-AUDIT-004｜P2｜精致素材运行时接入不足

原问题：素材包已经包含较完整的视觉与音效资产，但运行时代码只接入了其中一部分。

修复方式：补齐并验证素材接入。当前运行时代码、HTML 和 CSS 共引用 48 个素材路径，`assets/` 中 48 个素材全部被引用，缺失 0 个，未使用 0 个。已接入范围包括：池塘水面、舞台背景、石框、红鲤鱼和干扰鲤鱼游动帧、投食机、食物颗粒、莲叶/莲花/芦苇/水草/苔石/遮挡草、成功/失败涟漪、水花序列、HUD 图标、Logo、按钮贴图、玻璃面板、UI 点击音、投食音、成功/失败音、过关/通关音和环境循环水声。

### SP-AUDIT-005｜P2｜干扰鱼命名不统一

原问题：设计材料中出现“黑鲤鱼”“绿鲤鱼”“黑绿色干扰鱼”等口径。

修复方式：玩家可见文案统一为“干扰鲤鱼”。内部字段 `BlackNum` 和内部类型 `black` 保留，因为它们来自 P2 关卡表和既有数据结构；视觉层优先使用黑绿色干扰鲤鱼素材。

### SP-AUDIT-006｜P2｜暂停后重新演示不能恢复原局

原问题：从暂停帮助进入新手引导后，原关卡状态可能丢失。

修复方式：从暂停帮助进入引导时保存快照，内容包括关卡索引、当前关卡、总分、本关分、趋势、鱼状态、障碍、装饰、投食弹、水波、倒计时、食物数、错误数、冷却和开局 FX。引导完成后提供“返回原关卡”，恢复快照后继续正式训练；也保留“重新演示”和“放弃原局并重新训练”。

### SP-AUDIT-007｜P3｜开局动画模糊效果

修复方式：开局阶段增加水面短时模糊叠加和强波纹扩散；CSS 中也保留 `startFxBlur` 视觉状态，保证开局反馈与设计要求更接近。

### SP-AUDIT-008｜P3｜投食弹目标点固定导致视觉偏移

原问题：食物发射时固定目标点，鱼继续游动后，视觉上可能出现食物落点偏离鱼身。

修复方式：投食弹保存 `fishId`，飞行和绘制时持续追踪目标鱼当前位置；投食速度也适当提高，以降低高速鱼移动时的视觉偏差。

### SP-AUDIT-009｜P3｜重叠鱼点击层级

原问题：点击判定按生成顺序，可能与后绘制的视觉上层不一致。

修复方式：`pickFish()` 改为从鱼数组末尾向前检测；因为绘制也是前序到后序，最后绘制的鱼视觉上更靠上，点击结果现在与视觉层级一致。

### SP-AUDIT-010｜P3｜通关继续接口

原问题：最后一关“继续”缺少外部平台接入口。

修复方式：通关后构造完成数据 `payload`，优先调用 `globalThis.SilentPondOnGameComplete(payload)` 或 `globalThis.onSilentPondComplete(payload)`；如果不存在回调，则派发 `silentpond:complete` 事件；如果配置了 `nextGameUrl` 则跳转，否则单机版返回欢迎界面。

### SP-AUDIT-011｜P3｜HTML 注入扩展风险

处理方式：弹窗主体仍以内部静态模板为主，动态失败原因已通过 `escapeHtml()` 转义。奖励文案也做了转义处理，避免后续接入外部文本时形成直接注入风险。

### SP-AUDIT-012｜P3｜Axure `.rp` 语义级核验限制

处理方式：当前仍以可读取的 Excel 设计规范和 P2 关卡表为可执行规范来源。`.rp` 是 Axure 私有包，本轮没有做逐页面语义级自动解析；如果后续要求 100% 原型页面一致性，应提供 Axure 导出的 HTML 原型或人工交互标注。

## 4. 未改变的内容

- 50 关逐关数值没有被重写。
- 积分公式仍按设计文字执行：`Score + Scores × 剩余时间 / Time`，并四舍五入为整数。
- `BlackNum` 字段名保留，以维持和 P2 数值表的一致性。
- 核心玩法仍是“点击所有未投食红鲤鱼，避免干扰鲤鱼和重复投食”。

## 5. 当前仍需产品侧确认的点

1. `Fault` 已按中文“可错次数”落地。如果产品最终口径是“达到 Fault 即失败”，需要把 `faultPolicy` 改为 `failure_threshold`，并同步修改玩家文案。
2. P2 关卡表没有逐关鱼体大小和逐关变向时间字段。当前实现使用顶层默认值，同时兼容未来关卡级鱼体大小字段。
3. 文档中的积分示例若与“四舍五入”文字规则不一致，本实现以“四舍五入”文字规则为准。
